\vspace{0.5em}\noindent\textbf{Smart Healthcare AI Triage \& Appointment Booking Platform}

\vspace{0.5em}\noindent\textbf{Cloud-native Solution for AI-Powered Medical Triage and
Online Appointment Management}

\vspace{0.5em}\noindent\textbf{1. Executive Summary}

The Smart Healthcare Platform is engineered to modernize patient
reception, initial triage, and appointment booking workflows across
medical clinics and hospitals. The system leverages Artificial
Intelligence (AI) models hosted on \textbf{Amazon SageMaker} to classify
patient symptoms into 3 severity levels (Red - Yellow - Green) and
automatically generate medical summary reports for physicians prior to
consultations. Built on a Cloud-native architecture using \textbf{AWS
Cloud} (Cognito, EC2, RDS PostgreSQL, S3, CloudWatch), the platform
seamlessly handles thousands of concurrent requests from patients,
doctors, and reception staff.

\vspace{0.5em}\noindent\textbf{2. Problem Statement}

\emph{What's the Problem?} Healthcare facilities currently suffer from
severe reception counter congestion. Traditional appointment booking via
phone or in-person frequently leads to double-booking and prolonged
patient wait times. Additionally, doctors spend significant time
re-asking basic symptom details due to a lack of pre-consultation
summaries.

\emph{The Solution} The platform delivers a comprehensive end-to-end
solution:\\
1. \textbf{Real-time AI Chatbot:} Interacts with patients via WebSocket,
collects symptoms, and feeds data to \textbf{Amazon SageMaker} for
urgency triage and pre-consultation report generation. 2.
\textbf{Conflict-Free Booking Engine:} Implements row-level locking
(\textbf{Pessimistic Locking}) on \textbf{AWS RDS PostgreSQL} to
eliminate Race Conditions when multiple users attempt to book the exact
same slot. 3. \textbf{Flexible Two-Stage Payment:} Supports online
initial payments (consultation fee via PayOS/VNPay/Stripe) and secondary
payments (medications/lab tests at the counter). 4. \textbf{Security \&
RBAC:} Manages identity authentication through \textbf{AWS Cognito} and
secures sensitive health data using \textbf{UUID} masking.

\emph{Benefits and Return on Investment (ROI)} - Reduces front-desk wait
times by up to \textbf{60\%} through automated QR code check-in. -
Boosts doctor consultation efficiency by \textbf{30\%} with
AI-synthesized symptom reports. - Eliminates double-booking risks
completely, enhancing overall patient satisfaction. - Optimizes
infrastructure expenses via dynamic cloud elasticity on AWS.

\vspace{0.5em}\noindent\textbf{3. Solution Architecture}

The system adheres to a Multi-tier Web Architecture deployed on AWS
Cloud, divided into three main layers: Frontend (Next.js), Backend
Services (NestJS on EC2), and AI Services (Amazon SageMaker).

\emph{AWS Services Used} - \emph{Amazon Cognito}: Handles identity
management, sign-up/sign-in, and Role-Based Access Control (Patient,
Doctor, Receptionist, Admin). - \emph{AWS EC2}: Hosts Web Frontend
(Next.js) and Backend REST API / WebSocket Gateway (NestJS) using Docker
Containers. - \emph{Amazon SageMaker}: Deploys and serves real-time AI
endpoints for medical symptom triage. - \emph{Amazon RDS (PostgreSQL)}:
Managed relational database storing patient profiles, doctor schedules,
appointments, and billing data. - \emph{Amazon S3}: Stores static
assets, avatars, medical records, and appointment QR codes. - \emph{AWS
CloudWatch}: Aggregates system logs, monitors CPU/Memory utilization,
and triggers automated alerts. - \emph{AWS SES / SNS}: Sends automated
email and SMS appointment confirmations embedded with check-in QR codes.

\emph{Component Design} - \emph{Patient Portal (Next.js)}: Enables
patients to chat with the AI Bot, view doctor profiles, select time
slots, and complete online payments. - \emph{Healthcare Staff Portal
(Next.js)}:\\
- \textbf{Doctor Portal:} View daily appointment schedules, read AI
summary reports, input clinical diagnoses, and issue digital
prescriptions. - \textbf{Reception Portal:} Check in patients via QR
code scanner, generate invoices, and collect second-stage payments
(\texttt{POSTPAID}) at the counter. - \emph{Backend Microservices
(NestJS)}: Handles Core Business Logic, WebSocket Gateway, Payment
Integrations (PayOS/VNPay/Stripe), and PostgreSQL RDS connectivity.

\vspace{0.5em}\noindent\textbf{4. Technical Implementation}

\emph{Implementation Phases} The project is executed over an
\textbf{8-week} timeframe (2 months) structured as follows:\\
1. \emph{Weeks 1 - 2}: Requirements analysis, AWS Cloud architecture
design, PostgreSQL Schema design, and Base Source Code initialization
(Next.js + NestJS). 2. \emph{Weeks 3 - 4}: Infrastructure provisioning
(EC2, S3, RDS PostgreSQL), ORM integration (TypeORM/Prisma), and
Pessimistic Locking implementation. 3. \emph{Weeks 5 - 6}: AWS
CloudWatch setup, Amazon SageMaker AI endpoint integration, payment
gateway implementation (PayOS/VNPay/Stripe), and RBAC Dashboards. 4.
\emph{Weeks 7 - 8}: Stress testing (k6/Artillery), E2E testing, database
index optimization, Swagger API documentation, and final system demo.

\emph{Technical Requirements} - \emph{Frontend}: Next.js 14,
TailwindCSS, Socket.io-client, React Query. - \emph{Backend}: NestJS
Framework, TypeORM/Prisma, TypeScript, Socket.io. - \emph{Database}:
PostgreSQL 16.x on AWS RDS (Private Subnet). - \emph{AI/ML}: Python,
Amazon SageMaker Endpoints. - \emph{DevOps}: Docker, AWS CLI, GitHub
Actions (CI/CD).

\vspace{0.5em}\noindent\textbf{7. Risk Assessment}

\vspace{0.5em}\noindent\textbf{Risk Matrix}

\begin{itemize}
\tightlist
\item
  Race Condition (Double-Booking): High Impact, Medium Probability.
\item
  AI Service Timeout (SageMaker): Medium Impact, Low Probability.
\item
  Healthcare Data Privacy (IDOR): Very High Impact, Low Probability.
\end{itemize}

\vspace{0.5em}\noindent\textbf{Mitigation Strategies}

\begin{itemize}
\tightlist
\item
  \emph{Race Condition}: Implemented row-level Pessimistic Locking
  directly at the PostgreSQL database layer.\\
\item
  \emph{AI Timeout}: Designed a graceful fallback mechanism --- if the
  AI service times out, the system automatically routes the user to
  standard manual doctor selection without breaking the user
  experience.\\
\item
  \emph{Data Privacy}: Masked database IDs with UUIDs in URLs and
  anonymized sensitive patient metrics before streaming logs to
  CloudWatch. \#\#\# 8. Expected Outcomes
\item
  \textbf{Technical Enhancements:} Automates 80\% of patient reception
  and triage workflows; achieves \textgreater{} 99.9\% system
  availability on AWS Cloud.\\
\item
  \textbf{Long-term Value:} Provides standardized data structures for
  medical analytics and disease forecasting; offers seamless scalability
  to support multi-branch clinic chains in the future.
\end{itemize}
