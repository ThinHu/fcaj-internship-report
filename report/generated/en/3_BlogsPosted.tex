\vspace{0.5em}\noindent\textbf{\texorpdfstring{\href{3.1-Blog1/}{Blog 1 - AWS Bedrock
Knowledge Bases: The perfect ``missing piece'' for Serverless RAG
architecture}}{Blog 1 - AWS Bedrock Knowledge Bases: The perfect ``missing piece'' for Serverless RAG architecture}}

This blog introduces AWS Bedrock Knowledge Bases---a service that fully
automates the RAG pipeline (chunking, embedding, indexing) without the
need to self-manage complex Vector Database infrastructure. Applying a
Serverless RAG architecture helps the medical AI Assistant system easily
scale and automatically update new knowledge via Amazon S3.

\vspace{0.5em}\noindent\textbf{\texorpdfstring{\href{3.2-Blog2/}{Blog 2 - AWS Cognito:
The indispensable ``missing piece'' for Digital Healthcare
Systems}}{Blog 2 - AWS Cognito: The indispensable ``missing piece'' for Digital Healthcare Systems}}

This blog focuses on solving the multi-role identity and authorization
problem (Patients, Doctors, Receptionists) for a digital healthcare
platform. By integrating AWS Cognito, the project leverages Fully
Managed Identity features, RBAC authorization via JWT tokens, and secure
on-boarding flows, which help secure medical data and optimize
development costs.

\vspace{0.5em}\noindent\textbf{\texorpdfstring{\href{3.3-Blog3/}{Blog 3 - AWS S3 Bucket:
The Cloud-Native Storage ``Missing Piece'' for Digital Healthcare
Systems}}{Blog 3 - AWS S3 Bucket: The Cloud-Native Storage ``Missing Piece'' for Digital Healthcare Systems}}

This blog shares the experience of migrating the file storage system
(images, medical certificates, AI model weight files) from local servers
to Amazon S3. Moving files to S3 not only makes the backend
``stateless'' and easily scalable but also enhances absolute security
for sensitive medical data through Presigned URLs.
